# 開發

給修改 briefgen 程式的人看。使用方式見[使用指南](使用指南.md)，語法見[語法速查](語法速查.md)。

## 環境

```bash
pip install -e . -r requirements-dev.txt
python -m playwright install chromium
python -m pytest
```

執行依賴只寫在 `pyproject.toml`；`requirements-dev.txt` 是測試用的套件（pytest、playwright、pypdfium2、pillow 等）。版本號只寫在 `src/briefgen/__init__.py` 的 `__version__`，pyproject 與啟動器都從這裡讀取。

## 專案結構

```text
src/briefgen/
  __main__.py          python -m briefgen 進入點
  cli.py               命令列（build、watch）
  console.py           終端輸出設定（UTF-8）
  generator.py         載入 Markdown、生成 HTML、印出警告
  model.py             資料模型（Slide、Presentation）
  tags.py              行首格式解析（段落、儲存格、樹節點共用）、顏色名稱
  highlighter.py       程式碼語法高亮
  watch.py             即時預覽
  parsing/slides.py    切割投影片、標題與副標題、原始行號
  parsing/blocks.py    程式碼、表格、樹狀圖區塊
  render/html.py       HTML 渲染（段落、cont、清單、圖片、區塊）
  templates/template.html  版面與瀏覽器端行為（按鍵、縮放、列印）
tools/migrate_syntax.py    舊語法轉換工具
docs/                      使用者文件
examples/                  範例簡報與空白範本
tests/                     pytest 測試；tests/e2e/ 是瀏覽器端測試
launcher.py、start.bat      中文選單啟動器
```

## 資料流

1. `parsing/slides.py`：以單獨一行 `---` 切割投影片，取出 `#` 標題與 `##` 副標題；程式碼區塊內的 `---` 與 `#` 不影響分頁和標題。`Slide.source_lines` 記錄每個內容行在原始檔的行號，供警告使用。
2. `parsing/blocks.py`：抽出程式碼、`[table]`、`[tree]` 區塊，以佔位行取代，並回傳每行的原始行索引。
3. `tags.py`：`parse_format()` 是唯一的行首格式解析；錯誤不丟例外，而是放進 `warnings`。
4. `render/html.py`：渲染段落（cont 接續、清單）、圖片（本機圖片嵌成 data URI）與區塊；警告依行號排序後交給 callback。
5. `generator.py`：套用 `templates/template.html`，把警告以 `檔名:行號: 訊息` 印到 stderr。
6. `watch.py`：輪詢檔案修改時間，以 `http.server` 提供頁面；自動重新載入的程式碼只插在伺服器回應的頁面，寫到磁碟的 HTML 不含。

模板負責瀏覽器端的行為：按鍵與網址 hash、黑屏、樹狀圖縮放（`fitTrees`），以及列印版面。列印規則由 Jinja macro `print_rules` 同時產生給 `@media print` 與 `html.print-layout`，`beforeprint` 時套用列印版面再縮放。

## 在程式中使用

```python
from briefgen.generator import PresentationGenerator

gen = PresentationGenerator()
gen.load_from_markdown('講義.md')
gen.generate_html('講義.html')
```

## 測試

| 測試 | 內容 |
|---|---|
| `tests/test_golden.py` | `tests/fixtures/new/*.md` 的生成結果必須和 `tests/golden/*.html` 逐字相同，警告也必須等於 `EXPECTED_WARNINGS` |
| `tests/test_migrate_syntax.py` | `tests/fixtures/old/` 轉換後必須等於 `tests/fixtures/new/` |
| `tests/test_docs.py` | 文件與範例能無警告生成、相對連結有效、文件裡的指令能執行、沒有 emoji、語法速查和規格一致 |
| `tests/test_smoke.py` | 以子行程執行 CLI 與啟動器，模擬繁體中文 Windows 的終端編碼（cp950） |
| `tests/e2e/` | playwright 瀏覽器端測試：按鍵、樹狀圖縮放、列印、圖片、即時預覽 |
| `tests/e2e/test_fit.py` | docs/ 與 examples/ 的簡報每一頁在 1280×720 扣掉導覽列後不需要捲動（一般閱讀文件除外） |

`tests/fixtures/` 是凍結的測試資料，除了新增 edge case 以外不要修改。每個 edge case 只測一件事。

沒有安裝瀏覽器時 e2e 測試會自動略過；設定環境變數 `BRIEFGEN_REQUIRE_E2E=1` 時改為失敗（CI 就是這樣設定）。

commit 前必須確認 pytest 的結束碼為 0。不要把 pytest 的輸出接到 `tail`、`head` 等管線，管線會吞掉結束碼；要截短輸出就先存檔再看。

## 更新 golden

輸出改變時（渲染、模板、顏色等），golden 測試會失敗。流程：

1. 用目前的程式生成三份 fixture，和 `tests/golden/` 比對
2. 列出差異並確認每一處都是預期的變化（只改到該改的地方）
3. 確認後才用新的輸出覆蓋 `tests/golden/`
4. commit 訊息列出 golden 的變化

## CI

`.github/workflows/test.yml` 在 push 與 pull request 時，於 ubuntu-latest、windows-latest 各用 Python 3.11、3.12 執行：安裝套件與開發依賴、安裝 chromium、執行 pytest（設定 `BRIEFGEN_REQUIRE_E2E=1`）。失敗訊息會以 annotation 顯示在 GitHub 上。

`.gitattributes` 讓 SVG 在所有平台以 LF 取出，因為圖片會以位元組嵌入 HTML，換行不同會讓 golden 不一致。

## 文件分工

| 文件 | 讀者與內容 |
|---|---|
| `README.md` | 這是什麼、安裝、30 秒上手、文件連結 |
| `docs/使用指南.md` | 使用者的完整說明，依使用流程排列 |
| `docs/語法速查.md` | 一頁式語法表格，必須和 `CLAUDE.md` 的語法規格一致 |
| `docs/格式參考.md` | 用簡報展示所有格式的範例 |
| `docs/開發.md` | 本檔 |
| `CHANGELOG.md` | 各版本的變化，對應 git tag |

使用者文件的語法說明有改動時，要同步更新 `docs/語法速查.md` 與 `CLAUDE.md` 的語法規格。
